# v0.6.3 Release Plan

## Scope

Publish the existing repair candidate through a reviewed pull request into main.
Upgrade directly from v0.6.1 to v0.6.3 at the user's request. Preserve the current
website layout, update its download links and release history, and deploy the
existing production project. Do not modify the user's installed extension.

The scheduled monitor is paused. The interrupted live observation window is
not a completed three-hour stability test. Production idle and native sleep/wake
coverage must remain explicitly unverified. Pump delay investigation and new
diagnostic UI work remain deferred.

## Execution checkpoints

1. Add failing website/version consistency tests, then update package metadata,
   README downloads, changelog, and website content to v0.6.3.
2. Run type checking, the complete unit/integration suite, website contracts,
   isolated Chromium E2E, production build, and diff checks. Build and verify
   the ZIP and SHA-256, including manifest version and installation guidance.
3. Review the candidate diff, commit and push the branch, create and attach a PR,
   inspect its mergeability/checks, then merge without bypassing protections.
4. Fast-forward the clean primary main checkout and verify merged content.
   Publish the v0.6.3 GitHub Release from that exact main commit with ZIP and
   SHA-256. Verify published asset metadata and downloaded checksum.
5. Deploy the website to its existing production project. Verify READY status
   and the production alias using deployment metadata, not HTTP page fetching.
6. Report the merged PR, release, download, website, and remaining validation
   limits. Preserve the worktree and paused automation for traceability.

## Rollback and safety

Do not overwrite previous release assets, force-push, rewrite Git history, or
change production permissions. If a gate fails, stop publication and repair or
report the failure. Website publication follows the availability of its linked
GitHub asset. Preserve old version entries and the original monitoring record.
